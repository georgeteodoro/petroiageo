
# Objetivo
Os códigos dessa pasta se referem à preparação dos dados de porosidade distribuídos em vários poços para serem servidos ao algoritmo. 

## Arquivos necessários
É esperado que existam os seguintes arquivos de antemão:

- Arquivo csv com nome e coordenada de poços (`$WELLS_INFO_PATH`): Esse arquivo possui informações sobre os poços contidos no cubo sísmico como nome e coordenadas x e y relativas ao cubo sísmico. Deve ter as colunas: "Well, x_coord, y_coord, min_z, max_z". Well é simplesmente o nome do poço. x_coord e y_coord devem ser valores inteiros não negativos. min_z e max_z podem ser valores de ponto flutuante com `min_z < max_z`.

- Arquivos de porosidades ao longo dos poços: Esses arquivos possuem as medições das diferentes porosidades ao longo dos poços. Dessa forma, possuem a profundidade e medição de até três porosidades diferentes (densidade, sônica e neutrônica). Para o arquivo referente a cada poço, se existirem, é importante que os nomes das colunas sejam 'depth', 'neutron_por', 'density_por', 'sonic_por' e 'time'. Todas as colunas que não possuem esses nomes serão excluídas do arquivo final. Caso alguma das colunas indicadas não exista, ela será criada e completada com valores iguais a np.nan. Todas as colunas podem ser valores de ponto flutuante. É esperado que esses arquivos possuam linha de cabeçalho com os nomes das colunas e que os valores estejam separados por vírgula. 

- Áreas alvo e coordenadas (`$AREAS_COORDS_PATH`): Arquivo csv que delimita áreas de interesse no cubo sísmico baseado na concentração de poços. Criado a partir da análise da distribuição dos poços na área sísmica. De ter as seguintes colunas: "area, max_x, min_x, min_y, max_y". area é a identificação da área, podendo ser de qualquer tipo. As outras colunas devem ser valores inteiros não negativos com `min_x < max_x` e `min_y < max_y`

- Cubo sísmico (`$SEISMIC_FILE`): Arquivo npy de três dimensões com as medidas sísmicas com resolução de `SEISMIC_RESOLUTION` metros na dimensão de profundidade. Deve-se saber qual é o valor da resolução `SEISMIC_RESOLUTION`. É esperado que esse valor seja um valor inteiro positivo.

Pode ser necessários o seguinte arquivo:

- Tempo de início de dados no pré-sal por poço (`$START_TIME_PRE_SALT_PATH`): Arquivo csv que indica o tempo de medição do início dos dados disponíveis do pré-sal para cada poço. Importante ressaltar que o tempo não indica necessariamente o início do pré-sal ao longo do poço, apenas o início de dados amarrados que estejam dentro do pré-sal. Deve possuir duas colunas `Well` e `time`. A primeira indica o nome do poço e a segunda indica o tempo.

## Agregação dos dados de porosidade por área

Primeiramente, devemos agregar os arquivos de porosidade dos poços que residem dentro de uma mesma área alvo definida no arquivo de áreas alvo. Isso pode ser feito executando o seguinte script:
`python3 agg_area_por_files.py --target_area TARGET_AREA --areas_coords_path AREAS_COORDS_PATH --wells_info_path WELLS_INFO_PATH --wells_por_dir_path WELLS_POR_DIR_PATH --final_df_dir_path FINAL_DF_DIR_PATH`

A explicação de cada um desses parâmetros pode ser visto com:`python3 agg_area_por_files.py -h`. Mas, basicamente, TARGET_AREA é o nome da área alvo de onde agregar os arquivos de porosidade (se for igual a -1, executa para todas as áreas alvo), AREAS_COORDS_PATH é o caminho para o arquivo que possui as áreas e suas coordenadas, WELLS_INFO_PATH é o caminho para o arquivo que possui informações sobre cada poço, WELLS_POR_DIR_PATH é o caminho para a pasta que possui os arquivos com as porosidades de cada poço e FINAL_DF_DIR_PATH é o caminho para a pasta que receberá os arquivos agregados.
## Filtrar e tratar porosidades
Aqui, será realizado a filtragem por intervalo de profundidade ou tempo, a interpolação e possível agregação dos dados de porosidade de uma área. Isso pode ser feito executando o seguinte script:
`python3 treat_porosity_file.py --min_depth MIN_DEPTH --max_depth MAX_DEPTH --por_file POR_FILE --target_por_file TARGET_POR_FILE [--agg_strat {NONE,M_O_R,M_O_N}] [--rolling_w ROLLING_W] [--n_meters N_METERS] [--no_interp] [--by_time] [--start_time_pre_salt_path START_TIME_PRE_SALT_PATH] [--wells_info WELLS_INFO]`

A explicação para cada uma das opções pode ser vista ao executar `python3 treat_porosity_file.py -h`. Mas, basicamente, MIN_DEPTH e MAX_DEPTH definem o intervalo de profundidade ou tempo onde deverão ser filtrados os dados de porosidade de cada poço; POR_FILE é o caminho do arquivo que possui os dados de porosidade da área alvo produzido pelo script da seção anterior; TARGET_POR_FILE é o caminho alvo do arquivo csv a ser gerado; agg_strat deve receber uma de três opções {M_O_N, NONE, M_O_R} onde NONE não realiza nenhuma agregação sobre os dados de porosidade, M_O_N gera pontos para cada intervalo de N_METERS metros de profundidade ou medidas de tempo baseado na média dos pontos nesse intervalo e M_O_R aplica uma média móvel de acordo com a janela indicada em ROLLING_W. É esperado que ROLLING_W e N_METERS sejam valores inteiros positivos se utilizados. A opção `no_interp` serve para indicar que não deve ser feita a interpolação dos dados de porosidade. Isso serve para os casos em que as medições de porosidades dos poços não estão contínuas, ou seja, em profundidades ou tempo não perfeitamente sequenciais. A opção `by_time` indica que deve-se filtrar os dados usando da coluna que indica o tempo de medição. A opção `start_time_pre_salt_path` indica o caminho do arquivo `$START_TIME_PRE_SALT_PATH` descrito anteriomente e é utilizado somente se `by_time` tenha sido usado. Caso ele não seja provido, todo poço será filtrado pelo tempo indicado por MIN_DEPTH. O parâmetro `wells_info` indica o caminho do arquivo `$WELLS_INFO_PATH` já descrito anteriormente. Ele é necessário caso esteja usando a opção `by_time` e `start_time_pre_salt_path` tenha sido definido.

## Junção dos dados de porosidade com a sísmica
Aqui, será realizado o casamento entre os dados de porosidade tratados com o cubo sísmico. O cubo sísmico será filtrado de acordo com a área delimitada por uma área alvo e também será filtrado pelo intervalo de profundidade de acordo com a presença de dados de porosidade para essa área. Além disso, os valores sísmicos serão interpolados para que casem com as medições de porosidade. Isso pode ser feito executando o seguinte script:
`python3 filter_and_merge_seismic_por.py --por_file POR_FILE --area_info_file AREA_INFO_FILE --target_area TARGET_AREA --seismic_file SEISMIC_FILE --seismic_resolution SEISMIC_RESOLUTION --start_seismic_depth START_SEISMIC_DEPTH --target_seismic_file TARGET_SEISMIC_FILE --target_merge_file TARGET_MERGE_FILE [--no_interp] [--by_time] [--dont_merge]`

A explicação de cada parâmetro pode ser vista executando `python3 filter_and_merge_seismic_por.py -h`. Mas, basicamente, POR_FILE é o caminho para o arquivo de tratado gerado pelo script anterior, AREA_INFO_FILE é o caminho para o arquivo que possui informações sobre cada área alvo, TARGET_AREA é o nome/identificador da área alvo, SEISMIC_FILE é o caminho para o arquivo sísmico `.npy`, SEISMIC_RESOLUTION é o valor da resolução sísmica no eixo z, START_SEISMIC_DEPTH é a profundidade inicial real em metros presente no arquivo sísmico, TARGET_SEISMIC_FILE é o caminho alvo do arquivo sísmico tratado a ser gerado e TARGET_MERGE_FILE é o caminho alvo do arquivo csv que contém as porosidades e a sísmica relacionada para cada poço da área alvo. A opção `no_interp` serve para indicar que não deve ser feita a interpolação dos dados sísmicos. Isso serve para os casos em que as medições de porosidades dos poços não estão contínuas, ou seja, em profundidades não perfeitamente sequenciais. A opção `by_time` serve para indicar que a dimensão z do dado sísmico está em tempo. Dessa forma, serão usados os valores da coluna `time` de POR_FILE. A opção `dont_merge` indica que não é necessário realizar o merge do arquivo de porosidade com o sísmico. Assim, a única ação realizada pelo script é filtrar o dado sísmico e salvá-lo.
